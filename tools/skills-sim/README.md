# skills-sim — balance simulator for the skill system

Headless replica of the Chaos Arena battle loop (`src/use/useSpinnerGame.ts`) plus the ten
proposed skills. It produces every balance number in **`skills-feature.md` §3** (power
metric, singles, all 45 pairs, paired confirmation, per-spinner alternative, robustness)
and the economy projections in **§6.3**. Plain Node ≥ 20 ESM, no dependencies.

`skills.mjs` reads the skill level tables from `src/data/skillCatalog.ts` (single source) and
`data.mjs` reads the part tables, upgrade bonuses, the 100-stage table and `upgradeCost`
straight from the TS sources and aborts if any of 26 physics constants drifted from
`useSpinnerGame.ts` — a changed game rule shows up here, not as silently wrong numbers.

## What it measures

For a skill loadout **S** on a stage:

- **OFF = TTK₀ / TTK_S** — turns until the enemy team dies, player team immortal.
- **DEF = TTD_S / TTD₀** — turns until the player team dies, enemy team immortal.
- **PI = OFF × DEF** — the power index. The design cap is **PI ≤ 1.5** for the 2-slot
  loadout at level 10 (both spinners carry it, as in the game).

Each seed is also played as a normal battle for the win-rate ("easiness") tables. Seeds are
shared across configs (common random numbers); skill procs use a separate RNG stream.

## Run it

Always through the worker-budget wrapper (it caps the worker threads). From this folder:

```sh
B="$HOME/.claude/skills/worker-budget/budget.mjs"

# quick (seconds): the headline worst pair on its worst stage (skills-feature.md §0 / §3.5).
# Seeds are deterministic, so at the sweep's N these reproduce the doc exactly.
node "$B" run --want 8 -- node run.mjs --set custom --configs "phase_step+static_charge" --stages 30 --n 600 --out out/quick.json
node report.mjs out/quick.json                        # → 1.43 (as in §3.5); at --n 300 expect 1.43 ± ~0.08
node "$B" run --want 8 -- node confirm.mjs --pairs phase_step+static_charge --stages 30 --n 2000 --out out/quick-confirm.json
                                                      # → PI 1.407, 95 % CI 1.373–1.442 (as in §0)
# early-game gate (§3.10, ~1 min): all pairs at L5 on stage 11 — the grid maximum
node "$B" run --want 8 -- node run.mjs --set pairs --levels 5 --stages 11 --n 400 --out out/early.json
node report.mjs out/early.json --L 5                  # → top row Homing Rockets + Opening Salvo 1.26
node skillecon.mjs                                    # §6.3: typical @35 % → 2 maxed @33, all 10 @80

# full pair sweep (§3.5, ~35 min at 10 workers)
node "$B" run --want 10 -- node run.mjs --set pairs --levels 10 --n 600 \
  --stages 15,17,30,31,35,49,50,55,77,80,95,99,100 --out results/v7_pairs10.json
node report.mjs results/v7_pairs10.json --L 10        # --mode off|def|wr for the other views
```

Other tables: `--set singles --levels 1,5,10` (§3.4), `--set pairs --levels 1,5` (L1/L5
line), `--set custom --configs "a+b|c+d"` (per-spinner loadouts, §3.6; config lists from
`mkteams.mjs` / `mkrobust.mjs`), `--team glass|tank` and `--levelMode lock` (§3.7),
`confirm.mjs --team <t>` (paired CIs), `control.mjs tank 30 1500` (plain stat-buff control,
§3.7), `levelequiv.mjs` (skill power in part levels, PvP fairness §9.1),
`node econ.mjs` / `node skillecon.mjs` (§6.3; `SKILL_COST=150,100,…` env tries another price curve). Write result files
to
`results/<name>.json` with the names `fill.mjs` expects (listed at its top), then
`node fill.mjs` renders `out/skills-feature.preview.md`; `node fill.mjs --write` updates
`skills-feature.md` and refuses while any input is missing.

`results/` keeps the two headline files (the §3.5 sweep and its paired confirmation), plus the
WP10 re-verification (`v10_*`, see `results/v10_SUMMARY.md`). The §3.10 early grid is regenerated by
`--set all --levels 1,3,5 --stages 10,11,12,13,14,15,17,20 --n 400 --out results/v8_early.json`;
everything else is regenerated by the runs above. `out/` is scratch.

## Knobs

- **Level tables** (L1…L10 per skill) live ONLY in `src/data/skillCatalog.ts`;
  `skills.mjs` parses them at load (and aborts on a missing skill, a wrong level count or a
  non-finite value). Re-tune loop: edit the catalog on a scratch copy/branch, re-run the pair
  sweep, keep the worst pair ≤ 1.50 with ~3 % headroom, then `node fill.mjs --write` renders
  §4. `skills.mjs` keeps its own `SKILL_IDS` ORDER (pair keys and result files depend on
  it); the id set is asserted equal to the catalog's.
- **`SKILL_POWER_SCALE`** (catalog, §5) — global hot-fix multiplier on chances/percents. The
  sim applies the catalog's value (engine reads `SKILL_PARAMS`); `SKILL_POWER_SCALE=0.9 node …`
  overrides it to test a hot-fix without touching the catalog.
- **`GOV.OUT_MUL_CAP`** in `engine.mjs` — the per-hit skill multiplier clamp
  (`SKILL_HIT_MUL_CAP = 2.2`).
- **Player model** — `teamFor()` / `TEAMS` in `engine.mjs` (builds), `econLevel()` in
  `econ.mjs` (part level from income; `PROFILES` = the income assumptions), the player
  policy in `playerLaunch()`.
- Worker count follows `WORKER_BUDGET_WORKERS` (set by the wrapper), max 10.

## League calibration (`league.mjs`, LG0)

Fits the two sim-derived tables in `src/league/leagueMath.ts` (the file header repeats the
headline). `floor` reads the shipped `TIER_FLOOR_POWER` / `GATEKEEPER_LEVEL` back out of
`leagueMath.ts` and marks the shipped cell `OK` / `OUT`, so a re-run after an engine or
boss change is also the regression check. The battle replica is `bosses100.mjs`'s patched
engine (regenerated at start: ember / frost / chill traits, `opts.stage`).

```sh
node "$B" run --want 10 -- node league.mjs k --n 160 --out out/league-k.json        # ~2 min
node "$B" run --want 10 -- node league.mjs floor --n 1000 --span 1 --out out/league-floor.json
# sweeps while re-fitting: --gl bronze=2-3 (gatekeeper levels) --pw bronze=26-34 (floor powers)
node league.mjs --report out/league-k.json
```

**Expected score (2026-09-30).** `E = 1 / (1 + ((opp + P0) / (own + P0))^K)`,
**K = 6.45, P0 = 62**, maximum likelihood over 161 280 league battles (challenger policy vs
ghost NPC AI, 4 × 4 archetypes default/glass/tank/spiky, own part levels 4–48, power ratios
0.6–1.7, power = sum of the 4 part levels, timeouts = ½). Brier 0.198 (coin flip 0.250);
real vs predicted within 3.3 pts in every ratio bin and 2.6 pts in every E decile; E runs
~2 pts low throughout (challenger wins 52.1 % at parity). With the offset the per-level K is
flat (6.1–6.6 from L4 to L48); a plain ratio (P0 = 0, K 3.11, Brier 0.202) needed K from
1.3 at L4 to 4.9 at L48 because part upgrades add to shared base stats. The unexplained
variance is composition: at equal power tank wins 83 %, default 62 %, spiky 42 %, glass 22 %.

the gatekeeper level, 1 000 battles each).** Floor powers anchored on `econLevel` at stages
20/35/55/80/120/200; Bronze moved 32 → 26 and Platinum 100 → 101 to land inside 55–65 %.

**LM5 — skill weight in team power (`leagueSkillWeight.mjs`, 2026-09-30, 36 480 battles).**
Challenger = default team at part level L ∈ {8, 18, 30, 44} with a 2-skill team loadout
(5 pairs covering all 10 skills) at skill level s ∈ {2, 5, 10}; ghost = skill-less default
team at the challenger's power (shipped weight 0.8) × {0.85, 1, 1.15}. Result: a single
linear weight does not fit. ML w = 0.67 against E as shipped (0.41 after removing E's own
+0.17 logit bias seen on the skill-less control), but per cell it runs from 0.17 (L8, s10:
real 32 % vs E 50 %) to ≥ 3 (every L at s2: real ~61 % vs E 50 %). Skills are worth more
at higher part levels (they scale off stats) and the first levels are worth the most.
Averaged by skill level the error is +10.8 (s2), +3.7 (s5), −4.3 (s10) points. Superseded
by LG-PWR below: this run fought default-vs-default mirrors only, whose win curve against
ghost level is 2–3× steeper than E's, and moved the ghost up with the skill level — so it
confused "stronger ghost" with "weaker skills".

```sh
node "$B" run --want 10 -- node leagueSkillWeight.mjs --n 160 --out out/league-skillweight.json
```

**LG-PWR — skill power model (`leagueSkillPower.mjs`, 2026-10-01, 360 000 battles).**
Replaces the linear `0.8 × Σ skill levels` in `src/utils/playerBuild.ts` (`buildSkillPower`,
used by `buildPower`, the NPC generator and the opponent picker):

`skillPower = round((Σ part levels + 124) × Σ g(lv) / 1000)`,
`g = [5, 7, 9, 10, 11, 12, 13, 14, 15, 16]` ‰ for levels 1…10.

Skills scale off the team's stats (base stats included — hence the +124), and a skill's first
level is worth the most (5 ‰, then ~1 ‰ per level). Skill-less power is unchanged (Σ part
levels), so gatekeeper floors and stored skill-less `lpower` are unaffected. Grid = league.mjs
k's: 4 × 4 archetypes, challenger policy vs ghost NPC AI, part levels 6/12/20/30/44, ghost part
level × 0.8…1.45, loadouts 1+1 … 10+10 plus single skills and mixed levels (3+0, 10+0, 5+1,
10+2) over the five LM5 pairs; skill-less control 40 000 battles. Fit: maximum likelihood with
E's own control bias held fixed; base 124 / power-law g (a 4.68, p 0.52) rounded to a concave
integer table. Real − E (E runs ~2 pts low on the skill-less control as in the K fit):

| loadout | control | 1+1 | 2+2 | 3+3 | 5+5 | 7+7 | 10+10 | 3+0 | 10+0 | 5+1 | 10+2 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| linear 0.8 | +1.9 | +1.8 | +1.2 | −0.4 | −2.3 | −4.2 | −7.0 | +1.1 | −3.0 | −0.1 | −3.6 |
| LG-PWR | +1.9 | +2.0 | +1.7 | +1.1 | +1.7 | +2.0 | +2.1 | +1.3 | +2.1 | +2.0 | +2.1 |

| part level (skilled) | L6 | L12 | L20 | L30 | L44 |
|---|---|---|---|---|---|
| control | +2.1 | +2.4 | +2.0 | +1.4 | +1.4 |
| linear 0.8 | −5.0 | −1.9 | −1.9 | −0.5 | +1.0 |
| LG-PWR | +2.3 | +2.8 | +1.1 | +1.4 | +1.6 |

Worst single (part level × loadout) cell: linear −15.4 (L6, 10+10), LG-PWR +3.5 (6 400
battles each; control +2.1…2.4 at those levels). K / P0 refit with skilled cells included:
K 6.45, P0 67 — worse on the skill-less K grid (max ratio-bin error 3.3 → 4.3), so K = 6.45,
P0 = 62 stay. On LM5's default-mirror data the model still under-prices low skill levels
(net of control: +7 at 2+2, +3.5 at 5+5, +0.7 at 10+10) — mirrors are not what E is fitted on.

```sh
node "$B" run --want 10 -- node leagueSkillPower.mjs run --n 16 --nc 100 --out out/league-skillpower.json  # ~6 min
node leagueSkillPower.mjs report out/league-skillpower.json      # shipped buildPower vs linear 0.8
node leagueSkillPower.mjs fit out/league-skillpower.json [--base 124]
```
