# skills-sim — balance simulator for the skill system

Headless replica of the Chaos Arena battle loop (`src/use/useSpinnerGame.ts`) plus the ten
proposed skills. It produces every balance number in **`skills-feature.md` §3** (power
metric, singles, all 45 pairs, paired confirmation, per-spinner alternative, robustness)
and the economy projections in **§6.3**. Plain Node ≥ 20 ESM, no dependencies.

`data.mjs` reads the part tables, upgrade bonuses, the 100-stage table and `upgradeCost`
straight from the TS sources and aborts if any of 26 physics constants drifted from
`useSpinnerGame.ts` — a changed game rule shows up here, not as silently wrong numbers.

## What it measures

For a skill loadout **S** on a stage:

- **OFF = TTK₀ / TTK_S** — turns until the enemy team dies, player team immortal.
- **DEF = TTD_S / TTD₀** — turns until the player team dies, enemy team immortal.
- **PI = OFF × DEF** — the power index. The design cap is **PI ≤ 1.5** for the 2-slot
  loadout at level 10 (both spinners carry it, as in the game).

Each seed is also played as a normal battle for the win-rate ("easiness") tables. Seeds are
shared across configs (common random numbers); skill procs use a separate RNG stream.

## Run it

Always through the worker-budget wrapper (it caps the worker threads). From this folder:

```sh
B="$HOME/.claude/skills/worker-budget/budget.mjs"

# quick (seconds): the headline worst pair on its worst stage (skills-feature.md §0 / §3.5).
# Seeds are deterministic, so at the sweep's N these reproduce the doc exactly.
node "$B" run --want 8 -- node run.mjs --set custom --configs "phase_step+static_charge" --stages 30 --n 600 --out out/quick.json
node report.mjs out/quick.json                        # → 1.43 (as in §3.5); at --n 300 expect 1.43 ± ~0.08
node "$B" run --want 8 -- node confirm.mjs --pairs phase_step+static_charge --stages 30 --n 2000 --out out/quick-confirm.json
                                                      # → PI 1.407, 95 % CI 1.373–1.442 (as in §0)
# early-game gate (§3.10, ~1 min): all pairs at L5 on stage 11 — the grid maximum
node "$B" run --want 8 -- node run.mjs --set pairs --levels 5 --stages 11 --n 400 --out out/early.json
node report.mjs out/early.json --L 5                  # → top row Homing Rockets + Opening Salvo 1.26
node skillecon.mjs                                    # §6.3: typical @35 % → 2 maxed @33, all 10 @80

# full pair sweep (§3.5, ~35 min at 10 workers)
node "$B" run --want 10 -- node run.mjs --set pairs --levels 10 --n 600 \
  --stages 15,17,30,31,35,49,50,55,77,80,95,99,100 --out results/v7_pairs10.json
node report.mjs results/v7_pairs10.json --L 10        # --mode off|def|wr for the other views
```

Other tables: `--set singles --levels 1,5,10` (§3.4), `--set pairs --levels 1,5` (L1/L5
line), `--set custom --configs "a+b|c+d"` (per-spinner loadouts, §3.6; config lists from
`mkteams.mjs` / `mkrobust.mjs`), `--team glass|tank` and `--levelMode lock` (§3.7),
`confirm.mjs --team <t>` (paired CIs), `control.mjs tank 30 1500` (plain stat-buff control,
§3.7), `levelequiv.mjs` (skill power in part levels, PvP fairness §9.1),
`node econ.mjs` / `node skillecon.mjs` (§6.3; `SKILL_COST=150,100,…` env tries another price curve). Write result files
to
`results/<name>.json` with the names `fill.mjs` expects (listed at its top), then
`node fill.mjs` renders `out/skills-feature.preview.md`; `node fill.mjs --write` updates
`skills-feature.md` and refuses while any input is missing.

`results/` keeps only the two headline files (the §3.5 sweep and its paired confirmation; the
§3.10 early grid is regenerated by
`--set all --levels 1,3,5 --stages 10,11,12,13,14,15,17,20 --n 400 --out results/v8_early.json`);
everything else is regenerated by the runs above. `out/` is scratch.

## Knobs

- **`skills.mjs`** — the level tables (L1…L10 per skill). They must match
  `src/data/skillCatalog.ts` once that exists; edit here first, re-run the pair sweep, keep
  the worst pair ≤ 1.50 with ~3 % headroom, then copy the tables to the catalog and to
  `skills-feature.md` §4.
- **`SKILL_POWER_SCALE`** (catalog, §5) — global hot-fix multiplier on chances/percents. To
  test a value here, scale the tables in `skills.mjs` the same way (§5 lists which fields
  it touches) and re-run.
- **`GOV.OUT_MUL_CAP`** in `engine.mjs` — the per-hit skill multiplier clamp
  (`SKILL_HIT_MUL_CAP = 2.2`).
- **Player model** — `teamFor()` / `TEAMS` in `engine.mjs` (builds), `econLevel()` in
  `econ.mjs` (part level from income; `PROFILES` = the income assumptions), the player
  policy in `playerLaunch()`.
- Worker count follows `WORKER_BUDGET_WORKERS` (set by the wrapper), max 10.
